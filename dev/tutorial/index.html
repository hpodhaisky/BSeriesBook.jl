Tutorial

This page explains the package step by step, following the chapters of the book: first the conventions — how trees and B-series are represented — and then the main computations. Every code block is run when the documentation is built, so the output shown is the output of the current version. The Reference lists all functions.

using BSeriesBook

Trees and the standard numbering (Chapter 2)

The book numbers the rooted trees by Algorithm 3 ("Generate trees", Section 2.5). Every tree except t₁ = τ is the β-product tₙ = t_{L[n]} ∘ t_{R[n]}: the tree t_{R[n]} is grafted onto the root of t_{L[n]}, and R[n] ≤ R[L[n]] makes the decomposition unique. Within each order the trees are numbered in the order in which the algorithm produces them.

Trees(p) builds all trees up to order p in this numbering, together with the tree functions (Algorithm 4). Almost every other function takes this object as an argument.

T = Trees(6)
Trees: 37 trees up to order 6

A tree is a Tree: T[n] wraps the standard number n together with its Trees. It is shown with its number and its B⁺ form:

t = T[17]
t17 = [[[[τ]]]]

Functions on trees take a Tree; number gives back n. The type costs nothing at run time: a loop over Trees compiles to the same code as a loop over the numbers.

B-series (Chapter 3)

A B-series is a mapping a: T# → ℝ, T# = {∅} ∪ T, and stands for the series

\[B_h(a)\,y = a(\emptyset)\,y + \sum_{t} \frac{h^{|t|}\,a(t)}{\sigma(t)}\,F(t)(y),\]

the same normalisation as in BSeries.jl. In the package it is a vector over the standard numbering, a[t] = a(t), truncated at the order of its Trees; the value on the empty tree is a[empty_tree] (or a[∅]). The type records a(∅), following the sets 𝖡*, 𝖡 and 𝖡⁰ of Section 3.4 of the book: GeneralBSeries, CentralBSeries (a(∅) = 1) and VectorFieldBSeries (a(∅) = 0).

The exact solution E(t) = 1/t! is a central B-series:

The type is decided by the structure of a computation, never by the value of a(∅): the difference of two central series lies in 𝖡⁰, the sum of two central series in 𝖡*. A conversion such as CentralBSeries(g) checks the value of a(∅). Equality == and ≈ compare a(∅) as well; indexing with a range, broadcasting and other generic vector operations act on the coefficients a(tₙ) only and return plain vectors.

a = bseries(kutta4(), T)
typeof(a - E), typeof(a + E), (a + E)[empty_tree]
(VectorFieldBSeries{Rational{BigInt}}, GeneralBSeries{Rational{BigInt}}, 2//1)

Composition

compose(a, b), also written a * b, is the book's product ab: first a, then b (Theorem 3.9), a map 𝖡 × 𝖡* → 𝖡*,

\[(ab)(\emptyset) = b(\emptyset), \qquad (ab)(t) = b(\emptyset)\,a(t) + \sum_{\emptyset < t' \le t} a(t \setminus t')\, b(t'),\]

where t' runs over the subtrees of t that contain the root (the splittings above), and a(F) is the product of a over the trees of the forest F. This agrees with BSeries.compose(a, b). The first factor must be central (otherwise B_h(b) ∘ B_h(a) is not a B-series); the result has the type of b. Two half steps of the exact flow give one full step:

half = rescale(E, 1//2)          # E^(1/2)(t) = 2^-|t| / t!
half * half == E
true

The B-group: inverse, identity and powers.

a * inv(a) == one(a), a^3 == a * a * a, a^-1 == inverse(a)
(true, true, true)

A product with a non-central second factor has the type of the second factor:

g = GeneralBSeries(t -> 1//number(t), T, 2)
typeof(a * g), (a * g)[empty_tree]
(GeneralBSeries{Rational{Int64}}, 2//1)

The map slope and implicit stages

The B-series of hf(y₀) is D ∈ 𝖡⁰ (D(τ) = 1, D(t) = 0 otherwise), and for a central y the series of hf(B_h(y)y₀) is yD, with (yD)([t₁ ⋯ t_m]) = y(t₁) ⋯ y(t_m). slope(y) computes yD; for the identity it is D itself:

D = slope(identity_series(T))
coefficients(D)[1:4]
4-element Vector{Rational{BigInt}}:
 1
 0
 0
 0

slope(y, gamma) solves the implicit relation w = y + γ hf(w) in one pass over the standard numbering: it returns dw = wD with w = y + γ dw. With y the identity and γ = 1, w is the implicit Euler method:

w = identity_series(T) + slope(identity_series(T), 1)
w == bseries(RungeKuttaMethod(fill(1//1, 1, 1), [1//1]), T)
true

Number types

Functions are generic in the number type. The tableaux of the book are given as rationals; exact_solution returns Rational{BigInt}, and GeneralLinearMethod widens integer and rational coefficients to Rational{BigInt}, so that no overflow occurs at high orders. Floating-point tableaux stay floating point; use the atol keyword of order_of_accuracy:

order_of_accuracy(gauss2(), Trees(6); atol = 1e-12)
4

Substitution and the modified equation

substitute(b, a) is b ⋆ a for b in 𝖡⁰ (argument order as in BSeries.substitute): the method a applied to the vector field h⁻¹ B_h(b),

\[(b \star a)(t) = \sum_{\text{partitions of } t} b(\text{piece}_1)\cdots b(\text{piece}_m)\; a(\text{skeleton}),\]

with (b ⋆ a)(∅) = a(∅); the result has the type of a. A partition cuts a set of edges of t; the skeleton is t with every piece contracted to a vertex (tree_partitions):

tree_partitions(T[4])
4-element Vector{Partition}:
 Partition(root piece τ, pieces τ², skeleton [[τ]], multiplicity 1)
 Partition(root piece τ, pieces [τ], skeleton [τ], multiplicity 1)
 Partition(root piece [τ], pieces τ, skeleton [τ], multiplicity 1)
 Partition(root piece [[τ]], pieces ∅, skeleton τ, multiplicity 1)

The modified vector field b ∈ 𝖡⁰ with b ⋆ E = a: the exact flow of y' = h⁻¹ B_h(b)(y) reproduces the method. For the explicit Euler method,

Conjugacy (Algorithm 7)

Two central B-series a and b are conjugate to order p if x a x⁻¹ = b + O(h^{p+1}) for some x. conjugate_order applies Algorithm 7 (conjugacy_step) order by order. Conjugating the exact solution with any x gives a series that is conjugate to E to every order computed (here 6), although it differs from E already at order 3:

x = CentralBSeries(t -> order(t) == 2 ? 1//5 : 0//1, T)
ax = inv(x) * E * x
first_difference = order(first(t for t in T if ax[t] != E[t]))
first_difference, conjugate_order(ax, E)
(3, 6)

General linear methods and the underlying one-step method (Chapter 6)

This is the main addition of BSeriesBook.jl compared with BSeries.jl, which has no support for multivalue methods.

A general linear method (A, U, B, V) with s stages and r inputs computes, in one step,

\[Y = h\,A\,F(Y) + U\,y^{[n-1]}, \qquad y^{[n]} = h\,B\,F(Y) + V\,y^{[n-1]} .\]

Runge–Kutta methods (r = 1), linear multistep methods and many multistage–multivalue methods are special cases (Book, Section 6.4).

The underlying one-step method

The r input quantities approximate r different B-series of the solution. Kirchgraber (1986) and Stoffer (1993) showed that there is a starting method S and a one-step method Ẽ (both formal B-series) with

\[M \circ S = S \circ \tilde E ,\]

where M is one step of the general linear method: starting from S(y₀), the method behaves exactly like the one-step method Ẽ, observed through S. The order of the general linear method is the order to which Ẽ is conjugate to the exact solution E (Book, Section 6.6).

For a method in the partitioned form (6.6 a) of the book,

\[\begin{bmatrix} A & U \\ B & V \end{bmatrix} = \begin{bmatrix} A & \mathbf 1 & \hat U \\ b^T & 1 & 0^T \\ \hat B & 0 & \hat V \end{bmatrix}, \qquad 1 \notin \sigma(\hat V),\]

Ẽ and the starting method (identity, ξ) are computed tree by tree from the book's recursion (6.6 d) (details in Table 18 of the book):

\[\begin{aligned} \eta(t) &= A\,(\eta D)(t) + \hat U\,\xi(t), \\ \tilde E(t) &= b^T (\eta D)(t), \\ \xi(t) &= (I - \hat V)^{-1}\Bigl(\hat B\,(\eta D)(t) - \sum_{t' < t} \tilde E(t \setminus t')\,\xi(t')\Bigr), \end{aligned}\]

with (ηD)(t_ℓ ∘ t_r) = (ηD)(t_ℓ) ⊙ η(t_r). The sum is taken from the same table of splittings as compose. Every preconsistent method whose matrix V has 1 as a simple eigenvalue is first brought into the form (6.6 a) by a change of basis of the input vector (partitioned_form).

Checks

A Runge–Kutta method written as a general linear method must give its own B-series:

rk = kutta4()
underlying_one_step(GeneralLinearMethod(rk), T).E == bseries(rk, T)
true

Working together with BSeries.jl

A B-series of BSeriesBook.jl can be converted to a TruncatedBSeries of BSeries.jl via level sequences, for example to use functionality that only BSeries.jl offers:

using BSeriesBook
import BSeries, RootedTrees

T = Trees(5)
a = bseries(kutta4(), T)

s = BSeries.TruncatedBSeries{RootedTrees.RootedTree{Int, Vector{Int}},
                             eltype(a)}()
s[RootedTrees.rootedtree(Int[])] = a[empty_tree]
for t in T
    s[RootedTrees.rootedtree(BSeriesBook.level_sequence(t))] = a[t]
end

BSeries.order_of_accuracy(s)   # 4, as order_of_accuracy(kutta4(), T)
